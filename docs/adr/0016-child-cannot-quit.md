# 配对后的孩子端不能退出，后台服务每次都会拉起

配对后的孩子端拒绝所有普通退出（菜单、Cmd-Q、活动监视器的“退出”），不再弹家长密码框，菜单栏也不再显示退出入口。被强制结束、`kill` 或正常退出后，LaunchAgent 都会重新拉起它：`packaging/launch-agent.plist` 的 `KeepAlive` 从“只在异常退出时重启”改为 `true`。注销、重启、关机和 Sparkle 更新照常放行。配对前的孩子端仍可以用家长管理员密码退出，方便设置。

这修改了 ADR-0012 的一点：输入家长密码退出后，孩子端要等下次登录才回来，等于留了一个口子（`docs/reviews/2026-10-31-child-background-quit-verification.md`）。家长要停掉孩子端，走 `scripts/uninstall-auto-recovery.sh`，它会停止后台服务并删除配置；需要暂停管控时用家长端的规则或远程关闭，而不是退出。

始终重启带来两个新问题，一并处理：

- 登录项和 LaunchAgent 都会在登录时启动应用，Sparkle 更新也会自己重启应用，可能同时出现两个孩子端。启动时检查同一个应用 ID 的其他进程：由 launchd 启动的那个（`XPC_SERVICE_NAME` 等于任务标签）留下，结束其他的；不是 launchd 启动的发现已有一个在跑，就自己退出。装了 LaunchAgent 后，应用不再注册登录项。
- 更新退出后 launchd 会马上拉起旧程序，可能比新安装包落地还早。由 launchd 启动、且后台服务已是新配置时，孩子端每 30 秒比较一次磁盘上的构建号和自己的构建号，不一致就退出，让 launchd 拉起新版本；强制休息进行中不退出。

已经按旧脚本安装的家庭，配置还是“只在异常退出时重启”。孩子端窗口底部会显示“自动恢复需要更新”，家长重新运行 `scripts/install-auto-recovery.sh` 即可。

边界不变（ADR-0009）：只保证标准账户下的普通界面路径。孩子在终端里对自己会话的服务执行 `launchctl bootout`、删掉 App 等主动对抗，不在保证范围内。
